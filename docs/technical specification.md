### GeoWeedStation - 

#### Описание системы
**GeoWeedStation** — кроссплатформенное десктопное приложение оператора (GCS) для автоматизации агрономического мониторинга, управления БПЛА и построения цифровых карт засоренности полей. Программа выступает наземным аналитическим узлом, принимая данные с бортового комплекса `agrovision_onboard` либо работая полностью автономно в качестве локального центра обработки аэрофотоснимков и видео.

В онлайн-режиме станция обеспечивает планирование миссий, передачу полетных заданий по легковесному REST API и мониторинг телеметрии без риска зависания при обрывах связи. Программа бережно расходует ресурсы борта, запрашивая только структурированные метаданные и сжатые превью, а при необходимости выполняет локальный нейросетевой инференс на мощностях ПК без блокировки интерфейса.

В офлайн-режиме станция способна обрабатывать одиночные снимки, папки с кадрами и видеофайлы, динамически накладывая рамки детекции поверх изображения. Архитектура построена на едином модуле картографирования: данные о высоте, углах и координатах считываются напрямую из встроенных XMP-тегов снимков без использования сторонних файлов. Система одинаково корректно проецирует сорняки на тепловую карту как в метрах закрытого полигона по ArUco-маркерам, так и в глобальных координатах WGS84 для больших полевых массивов.


#### Функциональные требования (ФТ)

##### Общие функции

###### Переключение между онлайн и офлайн режимами работы
- Пользователь переключает глобальное состояние приложения через селектор в верхней панели главного окна.
- Переключение блокирует или скрывает интерфейсные элементы, не относящиеся к текущему режиму: блок сетевого подключения и телеметрии в офлайн-режиме, либо проводник локальных медиафайлов в онлайн-режиме.
###### Отображение текущего статуса фоновых процессов и прогресс-бара обработки
- В строке состояния (Status Bar) выводится текстовое описание текущей фоновой операции: чтение каталога, извлечение XMP, инференс кадра $N$ из $M$, построение тепловой карты.
- Прогресс-бар отображает относительный прогресс пакетных операций в процентах от 0 до 100%.
- Интерфейс предусматривает кнопку принудительной отмены текущей операции, переводящую фоновый воркер в состояние безопасного прерывания без утечек памяти.

##### Модуль цифрового картографирования (общий для онлайн и офлайн режимов)

###### Унифицированный входной интерфейс данных картографирования
- Модуль принимает на вход нормализованный контейнер пространственных данных кадра независимо от источника (потоковый JSON с дрона или результат локального разбора XMP).
- Контейнер содержит геометрическую позу камеры (высота, крен, тангаж, курс), систему координат (`local_aruco` или `wgs84`), оптические параметры матрицы и список рамок детекции (нормализованные пиксельные координаты $x, y, w, h$, класс, уверенность).
- При передаче контейнера без заполненных пространственных данных модуль не выполняет проецирование и возвращает код ошибки отсутствия привязки.

###### Блокировка режима картографирования при отсутствии пространственных тегов
- Перед запуском цикла проекции проверяется обязательный минимальный набор параметров: относительная высота над землей $H > 0$, координаты центра съемки, углы ориентации камеры.
- Если хотя бы один обязательный параметр отсутствует или имеет нулевое значение высоты, вкладка цифровой карты блокируется с выводом предупреждения: «Геопривязка отсутствует. Доступен только просмотр исходных изображений».
- Заблокированное состояние запрещает генерацию векторных слоев, тепловых матриц и запуск экспорта геоданных.

###### Проецирование пиксельных координат сорняков на плоскость поля
- Алгоритм пересчитывает координаты центров найденных рамок из пикселей матрицы в плоские метрические координаты поверхности земли.
- Входными переменными выступают фокусное расстояние объектива, физический размер матрицы (или вычисленные углы FOV), высота съемки $H$ и углы подвеса (Yaw, Pitch, Roll).
- В надирном приближении вычисляется линейный размер проекции кадра на землю, после чего с учетом угла курса (Yaw) определяется истинное декартово смещение сорняка относительно координат БПЛА в момент спуска затвора.

###### Построение точечного векторного слоя сорной растительности
- Вычисленные координаты каждого сорняка добавляются в единый массив векторных точечных объектов с атрибутами: ID, класс сорняка, confidence, пространственные координаты $(X, Y)$ или $(Lat, Lon)$.
- Векторный слой отрисовывается на двумерном холсте интерактивной карты в виде цветных маркеров, где цвет маркера соответствует классу обнаруженного растения.
- Пользователь имеет возможность кликнуть на конкретную точку на карте для просмотра миниатюры исходного снимка и параметров найденного объекта во всплывающей панели.

###### Генерация тепловой карты плотности засорения (Heatmap)
- Пространство обследованного участка разбивается на двумерную регулярную сетку ячеек заданного пользователем разрешения (по умолчанию $0.5 \times 0.5$ м или $1 \times 1$ м).
- Для каждой ячейки выполняется двумерная агрегация (Kernel Density Estimation либо прямое суммирование) количества точек сорняков, попадающих в ее границы.
- Матрица плотности визуализируется полупрозрачным растровым градиентом поверх координатной сетки (от темно-зеленого при нулевой засоренности до ярко-красного при максимальной).
- Интерфейс предоставляет бегунок регулировки прозрачности теплового слоя для возможности визуального сопоставления с точечными маркерами.

###### Расчет суммарного количества сорняков и удельной плотности
- Аналитическое ядро выполняет расчет общей площади обследованного участка на основе выпуклой оболочки (Convex Hull) всех проекций кадров либо по границам полетной сетки.
- Вычисляются агрегированные метрики: общее число сорняков по видам, средняя засоренность на квадратный метр, процент критически засоренной площади (ячейки с плотностью выше пороговой).
- Сводка показателей в реальном времени отображается в информационной панели картографического окна.

###### Экспорт результатов анализа в табличные форматы CSV и векторный GeoJSON
- Функция экспорта в CSV формирует структурированную таблицу со столбцами: `weed_id`, `class_name`, `confidence`, `coord_x`, `coord_y`, `coord_system`, `source_frame`.
- Экспорт в GeoJSON формирует стандартный файл пространственных данных `FeatureCollection` с геометрией типа `Point` и метаданными каждого растения внутри блока `properties`.
- При работе в СК `local_aruco` координаты экспортируются в плоских метрах с явным указанием локальной CRS в метаданных файла; при `wgs84` точки записываются в формате долгота/широта (EPSG:4326).

###### Формирование и сохранение растрового изображения карты засоренности в формате PNG
- Пользователь сохраняет текущее графическое состояние холста карты в высоком разрешении через диалог сохранения файла.
- На результирующий растровый слой накладываются координатная сетка, легенда классов, цветовая шкала плотности сорняков (heatmap scale bar) и масштабная линейка.
- Экспорт поддерживает выбор фонового слоя: белая подложка, прозрачный фон или композитное наложение на ортофотоплан.

##### Офлайн-режим (детально)

###### Выбор и загрузка одиночных изображений через системный проводник
- Пользователь открывает одиночный файл через стандартный диалог с фильтром по расширениям `.jpg`, `.jpeg`, `.png`, `.tif`, `.tiff`.
- Приложение считывает изображение в память с помощью OpenCV без блокировки графической подсистемы.
- Снимок масштабируется под размеры главного окна просмотра с сохранением исходного соотношения сторон.
###### Пакетная загрузка директории с серией аэроснимков для последовательного анализа
- Пользователь указывает папку, после чего приложение производит рекурсивное сканирование файлов поддерживаемых форматов.
- В интерфейсе формируется интерактивный список файлов с отображением имени, размера, статуса обработки и индикатора наличия XMP-метаданных.
- Запуск пакетной обработки инициирует последовательный проход воркера по списку с автосохранением промежуточных результатов в локальную сессию.
###### Открытие и воспроизведение видеофайлов встроенным медиаплеером
- Пользователь загружает видеозаписи облетов в форматах `.mp4` и `.avi`.
- Видеоплеер реализует стандартные элементы управления: воспроизведение, пауза, перемотка по таймлайну
- Декодирование видеопотока выполняется через `cv2.VideoCapture` в изолированном потоке, гарантируя передачу готовых кадров в UI без пропуска кадров и задержек рендеринга.
###### Детекция сорных растений на фото с помощью локальной модели ONNX Runtime
- Загруженное изображение преобразуется в тензор (нормализация, транспонирование каналов, resize с сохранением aspect ratio через letterbox).
- Инференс выполняется через локальную сессию `onnxruntime.InferenceSession` с автоматическим выбором доступного провайдера (CPUExecutionProvider либо аппаратное ускорение при наличии).
- Модуль выполняет постпроцессинг: фильтрацию по порогу уверенности (confidence threshold) и исключение перекрывающихся рамок методом Non-Maximum Suppression (NMS).
- Результаты детекции возвращаются в виде нормализованных Bounding Boxes с идентификаторами классов и метками уверенности.
###### Потоковая детекция объектов на видео с отрисовкой рамок классов в реальном времени
- Кадры из видеопотока передаются в фоновый инференс-воркер с настраиваемым интервалом пропуска (детекция каждого $N$-го кадра для оптимизации FPS).
- На промежуточных кадрах координаты рамок интерполируются либо удерживаются из предыдущего шага инференса.
- Отрисовка рамок, названий классов и confidence осуществляется непосредственно в буфере отображения перед отправкой кадра на экран.
###### Извлечение пространственных метаданных съемки напрямую из XMP-тегов
- При открытии каждого графического файла парсер считывает блок метаданных формата XML/XMP, встроенный в бинарную структуру JPEG или TIFF, без привлечения сторонних служебных текстовых файлов.
- Модуль изолирует пространства имен `drone-dji`, `Camera` и специализированный профиль `agro`.
- При нарушении структуры XMP или повреждении тегов модуль возвращает структурированное исключение и помечает файл как «снимок без метаданных».
###### Парсинг относительной высоты, углов подвеса и оптических параметров камеры из XMP
- Из блока XMP извлекаются теги относительной высоты оптического центра над поверхностью земли (`drone-dji:RelativeAltitude`).
- Считываются углы пространственной ориентации подвеса и камеры: курс (`drone-dji:GimbalYawDegree`), тангаж (`drone-dji:GimbalPitchDegree`), крен (`drone-dji:GimbalRollDegree`).
- Извлекаются калибровочные и оптические характеристики объектива: эквивалентное или физическое фокусное расстояние (`Camera:PerspectiveFocalLength`), координаты главной точки матрицы (`Camera:PrincipalPoint`), список зарегистрированных спектральных каналов (`Camera:BandName`).
###### Чтение координат в локальной и глобальной системах из метаданных
- Парсер проверяет тип заявленной системы координат через тег `agro:CoordinateSystem`.
- Если указана система `local_aruco`, считываются плоские координаты в метрах полигона из тегов `agro:CameraX` и `agro:CameraY`.
- Если указана глобальная система, считываются широта и долгота из тегов `drone-dji:GpsLatitude` и `drone-dji:GpsLongitude` с проверкой валидности полушарий.
- Полученные данные типизируются и передаются в унифицированный контейнер кадра для последующей отправки в модуль картографирования.
###### Интерактивный просмотр изображений с масштабированием и управлением рамками
- Холст просмотра поддерживает плавное панорамирование (drag-and-drop) и масштабирование колесом мыши с центрированием относительно курсора.
- Пользователь имеет возможность послойно включать и выключать отображение ограничивающих рамок, текстовых меток классов и значений confidence.
- Реализована панель фильтрации, позволяющая динамически скрывать с кадра сорняки определенных классов или объекты с показателем уверенности ниже заданного ползунком порога.


##### Онлайн-режим (Взаимодействие с БАС agrovision_onboard)
###### Подключение и опрос готовности бортового сервиса
- Ввод сетевого адреса (IP-адрес и порт) одноплатного компьютера БПЛА для установки HTTP-соединения.
- Выполнение первичного тестового запроса к методу GET /status для проверки доступности сервиса и чтения текущего состояния системы (ожидание, активный пресет, готовность модулей).
- Визуальная индикация сетевого статуса в интерфейсе (подключено, переподключение, тайм-аут, ошибка соединения).
- Фоновый опрос состояния борта без блокировки графического интерфейса с настраиваемым периодом (1–2 Гц) и таймаутом запроса не более 2 секунд.
- Механизм отказоустойчивости: сохранение работоспособности приложения и автоматические повторные попытки опроса при кратковременных обрывах радиоканала Wi-Fi.

###### Планирование полетной миссии и расчет маршрутной сетки
- Задание пространственных границ обследуемого полигона по двум опорным диагональным точкам: верхний левый угол (X1, Y1) и нижний правый угол (X2, Y2).
- Выбор целевой рабочей системы координат: локальная метрическая СК маркерного поля (local_aruco) для соревновательного куба 3х3х3 м или глобальная геодезическая СК (wgs84).
- Задание рабочей высоты полета над поверхностью (Z) и шага сканирующей сетки в метрах на основе фокусного расстояния и углов обзора камеры.
- Автоматическая генерация упорядоченного массива маршрутных точек (Waypoint) по траектории типа «галсы/змейка» с фиксацией целевых координат (x, y, z) и курсового угла (yaw).
- Двумерная интерактивная визуализация сгенерированного маршрута и расчетных точек остановки на картографическом холсте до момента отправки на дрон.

###### Конфигурирование режимов выполнения задания
- Переключение базового режима выполнения миссии на борту:
  - Режим чистого сбора данных (COLLECTION_ONLY / use_model=False): облет точек без загрузки нейросети в память одноплатника, только синхронная фиксация кадров со встроенными XMP-тегами.
  - Последовательный режим аналитики (INFERENCE_SEQUENTIAL / use_model=True): зависание на каждой точке, выполнение бортового инференса легковесной моделью, пересчет пикселей в координаты на борту и сохранение результатов детекции.
- Выбор флагов сохранения данных на накопитель БПЛА: флаг сохранения графических файлов (save_images) и флаг сохранения файлов метаданных детекции (save_metadata).
- Валидация конфигурации перед стартом: запрет отправки задания с отключенным сохранением изображений в режиме сбора данных (COLLECTION_ONLY) во избежание холостого полета.
###### Диспетчеризация миссии и управление полетным циклом
- Сериализация параметров миссии в JSON-структуру и передача полетного задания на борт БПЛА через метод POST /start.
- Прием ответа бортового сервиса, регистрация уникального идентификатора миссии (run_id) и фиксация абсолютного пути к изолированной директории запуска на дроне (`runs/run_<id>/`).
- Блокировка интерфейса редактирования маршрутных точек и параметров съемки на время активного выполнения миссии.
- Отправка команды принудительного прерывания полета через вызов метода POST /stop с возможностью выбора сценария аварийного завершения: немедленная вертикальная посадка на текущей позиции (action="land") либо возврат аппарата в точку старта (action="return").
- Корректная обработка подтверждения посадки от дрона и перевод интерфейса в режим ожидания выгрузки данных.

###### Мониторинг полетной телеметрии в реальном времени
- Непрерывный разбор телеметрического пакета из ответа метода GET /status в отдельном фоновом воркере.
- Отображение текущего этапа полета дрона (ожидание, взлет, движение к точке N из M, зависание и съемка, посадка, миссия завершена или ошибка).
- Отображение текущих декартовых или географических координат аппарата (X, Y, Z) и текущего угла курса (Yaw) в информационной панели станции.
- Отрисовка динамического маркера БПЛА с вектором направления оптической оси камеры поверх координатной сетки карты.
- Контроль счетчика успешно зафиксированных кадров и отслеживание флага готовности данных (ready_for_download) для завершения сеанса.

###### Прием результатов бортовой аналитики и онлайн-картографирование
- Опрос и загрузка промежуточных метаданных детекции через метод GET /runs/{id}/data?type=summary_json непосредственно в процессе выполнения последовательного режима с нейросетью.
- Передача принятых метаданных в общий модуль цифрового картографирования (MapEngine) для моментального нанесения сорняков на точечный слой и обновления тепловой карты (Heatmap) прямо во время полета.
- Опциональный выборочный запрос сжатых превью-изображений контрольных точек через GET /runs/{id}/data?point={N} для оперативного визуального контроля качества съемки оператором.

###### Менеджер бортовых запусков и архивных данных
- Запрос полного реестра выполненных миссий с бортового накопителя через метод GET /runs.
- Формирование структурированной таблицы запусков с выводом идентификатора run_id, даты и времени старта, итогового статуса выполнения, объема занятой памяти в мегабайтах и типов сохраненного контента.
- Скачивание полного пакета материалов выбранной миссии в виде единого ZIP-архива через метод GET /runs/{id}/data?type=archive.
- Автоматический разбор скачанных графических файлов встроенным парсером XMP станции (извлечение параметров drone-dji, Camera и agro без привлечения сторонних текстовых файлов).
- Запуск вторичной локальной обработки на ПК: пакетный прогон скачанных сырых кадров через локальный ONNX Runtime (для миссий, выполненных в режиме сбора данных без нейросети) с последующей передачей результатов в картографический модуль.
- Прямой вызов метода DELETE /runs/{id} для удаления выбранной директории запуска с накопителя одноплатника после успешной выгрузки данных на наземную станцию с подтверждением освобожденного объема диска.

#### Нефункциональные требования (НФТ)

- Выполнение нейросетевого инференса и декодирования видео строго в фоновых потоках QThread.

- Отображение изменения позы дрона на карте с задержкой отрисовки относительно прихода телеметрического пакета не более 100 мс.

- Выделение сетевого клиента взаимодействия с дроном в автономную библиотеку с фиксированным программным интерфейсом (API Client), исключающую прямые зависимости от модулей отображения.
- Изоляция парсера графических контейнеров и XMP-метаданных в отдельный функциональный модуль без привязки к конкретным библиотекам компьютерного зрения.
- Независимость интерфейса от формата нейросетевых моделей: программный модуль детекции абстрагирован от конкретного фреймворка исполнения тензоров.
- Отсутствие взаимных блокирующих циклических импортов между пакетами графического интерфейса, фоновых воркеров и математических модулей.

##### Расширяемость аналитического и картографического ядер
- Поддержка быстрого подключения новых нейросетевых архитектур детекции и сегментации через реализацию единого абстрактного базового класса детектора.
- Возможность расширения перечня поддерживаемых систем координат за счет абстрагирования модуля геодезических трансформаций и подключения дополнительных проекций EPSG.
- Поддержка добавления новых алгоритмов построения тепловых матриц плотности (KDE, взвешенное гауссово размытие, подсчет по гексагональной сетке) без изменения структуры холста карты.
- Архитектурная готовность к переходу от плоской надирной проекции к расчету координат с учетом цифровой модели рельефа (DEM / DTM) при наличии матриц высот местности.
- Возможность внедрения новых выходных форматов экспорта (Shapefile, KML, GeoTIFF) путем добавления независимых сериализаторов в модуль сохранения геоданных.

##### Асинхронность и управление вычислительными ресурсами
- Выделение долгоживущих фоновых сервисов (сетевой опрос, плеер видеопотока) в постоянные управляемые потоки QThread с явным жизненным циклом (запуск, пауза, остановка).
- Использование пула потоков QThreadPool с задачами QRunnable для параллельного извлечения метаданных и предварительной обработки списков изображений.
- Архитектурная поддержка механизма отложенной (ленивой) загрузки тяжелых ресурсов: веса нейросетевых моделей инициализируются только при фактическом запросе на инференс.
- Корректное освобождение дескрипторов файлов, видеопотоков OpenCV и системных хэндлов ONNX Runtime при завершении операций или аварийном прерывании воркеров.
- Независимость потока отрисовки графики от темпа поступления новых детекций за счет использования промежуточных потокобезопасных очередей кадров.




#### Термины и определения

##### Основные понятия и сущности системы
- Наземная станция оператора (GeoWeedStation): программный комплекс для управления миссиями БПЛА, мониторинга телеметрии, локального нейросетевого анализа и формирования цифровых карт засоренности полей.
- Бортовой сервис (agrovision_onboard): фоновый программный модуль на одноплатном компьютере дрона, выполняющий автономный полет по точкам, съемку и первичную обработку данных.
- Картографическое ядро (MapEngine): изолированный вычислительный модуль станции, выполняющий проецирование пиксельных координат сорняков в метрические или географические координаты и построение слоев карты.
- Контейнер кадра (FramePayload): нормализованная программная структура данных, объединяющая массив изображения, список найденных областей детекции и пространственную привязку.
- Локальная система координат (local_aruco): декартова метрическая система координат с началом отсчета (0, 0, 0) в базовом ArUco-маркере полетного куба соревнований.
- Глобальная система координат (wgs84): общеземная географическая координатная система, выраженная в широте и долготе (EPSG:4326), используемая для крупномасштабных полевых съемок.
- Карта засоренности: двухслойная геопространственная модель участка, состоящая из точечного векторного слоя расположения сорных растений и растрового теплового слоя (Heatmap) плотности биомассы на квадратный метр.
- Ограничивающая рамка (Bounding Box / BBox): плоские нормализованные координаты прямоугольной области кадра (xmin, ymin, xmax, ymax), охватывающей обнаруженную сорную растительность с указанием класса и вероятности.
- Надирная съемка: положение съемочной камеры, при котором оптическая ось направлена строго вертикально вниз к поверхности земли (угол тангажа Pitch $\approx -90^\circ$).
- Встроенные метаданные XMP (Extensible Metadata Platform): расширяемый формат внедрения текстовых XML-метаданных непосредственно в заголовок графического файла без использования сторонних текстовых файлов.

#### Модель предметной области (Ключевые сущности)

- Полетное задание (MissionTask): декларативная структура миссии, включающая идентификатор, рабочую систему координат (`local_aruco` или `wgs84`), параметры высоты полета, признак активации бортовой нейросети и упорядоченный массив путевых точек (Waypoint).
- Маршрутная точка (Waypoint): пространственная координата целевого перемещения БПЛА, содержащая плановые координаты $(X, Y)$ или $(Lat, Lon)$, относительную высоту полета $Z$ и требуемый курсовой угол аппарата (Yaw).
- Пространственная поза камеры (CameraSpatialPose): вектор ориентации оптической оси в момент спуска затвора, включающий пространственные координаты точки съемки, относительную высоту над подстилающей поверхностью и углы ориентации подвеса (Roll, Pitch, Yaw).
- Оптический паспорт сенсора (SensorOptics): набор калибровочных характеристик камеры, содержащий физическое или эквивалентное фокусное расстояние, углы обзора матрицы (FOV по горизонтали и вертикали), координаты главной точки (Principal Point) и перечень зарегистрированных спектральных каналов.
- Обнаруженный сорняк (DetectedWeed): атомарный объект детекции, содержащий класс сорного растения, оценку достоверности алгоритма (confidence), плоские нормализованные координаты рамки (Bounding Box) в кадровом пространстве и вычисленные метрические координаты на поверхности поля.
- Унифицированный контейнер кадра (FramePayload): агрегированная структура данных, передаваемая в картографическое ядро и содержащая растровый массив изображения, список объектов детекции и привязанный экземпляр пространственной позы (при ее наличии в метаданных).
- Цифровая карта поля (WeedMap): результирующая геопространственная модель обследованной территории, включающая точечный слой найденных сорняков, регулярную растровую матрицу плотности (Heatmap), общую полигональную границу участка и сводные статистические показатели засоренности.
- Сессия обработки (ProcessingSession): рабочий контекст наземной станции, агрегирующий список загруженных медиафайлов, текущий прогресс пакетной обработки, лог событий и активные векторные слои.
- Бортовой запуск (DroneRun): модель архивной или текущей сессии на дроне, включающая run_id, путь к директории `runs/run_<id>/`, дату/время старта, размер на носителе и флаги доступности файлов. 
- Пакет бортовых детекций (SummaryDetections): легковесный структурированный JSON-документ с борта, содержащий массив найденных сорных растений с предварительно рассчитанными координатами без передачи самих растровых изображений.
- Телеметрический статус (DroneStatus): модель оперативного ответа эндпоинта /status с текущим состоянием автопилота, индексом активной путевой точки и пространственной позой аппарата.

##### Структура графических файлов и представление XMP-метаданных
- Формат графического контейнера: снимок представляет собой растровый файл JPEG (для трехканальных RGB-изображений) или TIFF (для многоканальных мультиспектральных данных), в заголовочную секцию которого (App1-маркер для JPEG) внедрен текстовый XML-блок метаданных стандарта XMP.
- Внутренний контейнер метаданных: данные упакованы в открывающий тег `<x:xmpmeta>` с корневым элементом `rdf:RDF` и описателем свойств `rdf:Description`, содержащим три изолированных пространства имен (`drone-dji`, `Camera`, `agro`).
- Параметры высоты и ориентации в кадре:
  - `drone-dji:RelativeAltitude` — относительная высота оптического центра над уровнем земли в метрах (например, `+1.85`).
  - `drone-dji:GimbalYawDegree` — азимутальный угол (курс) направления объектива в градусах (диапазон от $-180.0^\circ$ до $+180.0^\circ$).
  - `drone-dji:GimbalPitchDegree` — угол наклона оптической оси по тангажу (значение $-90.0^\circ$ соответствует надирной съемке строго вниз).
  - `drone-dji:GimbalRollDegree` — угол крена оптической оси камеры в градусах.
- Параметры съемочной системы и оптики:
  - `Camera:PerspectiveFocalLength` — калиброванное фокусное расстояние объектива в миллиметрах (например, `4.5`).
  - `Camera:PrincipalPoint` — смещение главной точки матрицы относительно центра кадра в пикселях (формат записи `"cx,cy"`).
  - `Camera:BandName` — строковый идентификатор спектрального диапазона съемки (`RGB`, `RedEdge`, `NIR`).
- Пространственные координаты точки съемки:
  - В локальном режиме (`agro:CoordinateSystem="local_aruco"`): декартовы координаты оптического центра в метрах относительно базы куба соревнований, записанные в тегах `agro:CameraX` и `agro:CameraY`.
  - В глобальном режиме (`wgs84`): геодезическая широта `drone-dji:GpsLatitude` и долгота `drone-dji:GpsLongitude` в десятичных градусах.
- Листинг структуры XMP-блока внутри графического файла:
```xml
<x:xmpmeta xmlns:x="adobe:ns:meta/">
  <rdf:RDF xmlns:rdf="[http://www.w3.org/1999/02/22-rdf-syntax-ns#](http://www.w3.org/1999/02/22-rdf-syntax-ns#)">
    <rdf:Description rdf:about=""
        xmlns:drone-dji="[http://www.dji.com/drone-dji/1.0/](http://www.dji.com/drone-dji/1.0/)"
        xmlns:Camera="[http://pix4d.com/camera/1.0/](http://pix4d.com/camera/1.0/)"
        xmlns:agro="[http://geosaero.ru/agro/1.0/](http://geosaero.ru/agro/1.0/)"
        drone-dji:RelativeAltitude="+2.00"
        drone-dji:GimbalYawDegree="+15.0"
        drone-dji:GimbalPitchDegree="-90.0"
        drone-dji:GimbalRollDegree="0.0"
        Camera:PerspectiveFocalLength="3.6"
        Camera:PrincipalPoint="1280.0,960.0"
        Camera:BandName="RGB"
        agro:CoordinateSystem="local_aruco"
        agro:CameraX="1.50"
```
