# GeoWeedStation — Архитектурная документация

## 1. Обзор архитектуры

Проект **GeoWeedStation** построен по строгой слоистой архитектуре с разделением ответственности (Model-View-Controller / Clean Architecture):

```
+-------------------------------------------------------+
|                    UI (PySide6)                       |
|   MainWindow, ImageViewer, VideoPlayer, MapCanvas,    |
|   MissionControl, TelemetryPanel, RunsTable, Dialogs  |
+-------------------------------------------------------+
                           │
                    Qt Signals / Slots
                           ▼
+-------------------------------------------------------+
|                 Controllers (MVC)                     |
|   AppController, OfflineController, OnlineController, |
|   MapController, ExportController, RunsController     |
+-------------------------------------------------------+
         │                         │
         ▼                         ▼
+---------------------+   +-----------------------------+
|    Workers (QThread)|   |     Network Layer           |
|  BatchImageWorker   |   |   DroneClient (REST API)    |
|  VideoWorker        |   |   DownloadManager           |
|  TelemetryWorker    |   |   ExponentialBackoff        |
|  CommandWorker      |   +-----------------------------+
|  DownloadWorker     |                  │
+---------------------+                  │
         │                               │
         └───────────────┬───────────────┘
                         ▼
+-------------------------------------------------------+
|              Core Domain (Pure Python)                |
|   xmp_parser, onnx_detector, map_engine (projector,   |
|   weed_map, heatmap, statistics, exporter), planner   |
+-------------------------------------------------------+
                         │
                         ▼
+-------------------------------------------------------+
|               Schemas & Configuration                 |
|   Pydantic DTO (payload, entities, mission, map,      |
|   telemetry, onboard_api), AppSettings                |
+-------------------------------------------------------+
```

### Архитектурные инварианты:
1. **Изоляция ядра (`core/` и `schemas/`)**: эти слои написаны на чистом Python и **не содержат зависимостей от PySide6**. Это гарантирует возможность запуска инференса, парсера XMP и картографического движка в консольных утилитах, CLI и headless-тестах.
2. **Низкая связанность представлений (Views)**: Виджеты UI не выполняют дисковых операций ввода-вывода, не обращаются к сети и не выполняют инференс. Они только визуализируют переданные DTO и эмитируют пользовательские сигналы.
3. **Контроллеры как оркестраторы**: Контроллеры являются единственным связующим звеном между событиями графического интерфейса, фоновыми потоками и картографическим движком.

## 2. Потоковая модель и реактивное взаимодействие

Главный поток приложения (`GUI Main Thread`) никогда не блокируется длительными операциями. Любые вычисления свыше нескольких миллисекунд вынесены в специализированные воркеры (`QThread`):

| Воркер | Назначение | Поток выполнения |
|---|---|---|
| `TelemetryWorker` | Опрос REST API `/status` (0.5–2.0 Гц) | Выделенный `QThread` |
| `CommandWorker` | Дискретные запросы (`/start`, `/stop`, `/runs`) | Выделенный `QThread` |
| `DownloadWorker` | Потоковое скачивание ZIP-архивов и распаковка | Выделенный `QThread` |
| `BatchImageWorker` | Чтение JPEG/TIFF, извлечение XMP, ONNX-инференс | Выделенный `QThread` |
| `VideoWorker` | Декодирование видеопотока через OpenCV + детекция | Выделенный `QThread` |

### Межпоточный обмен:
- Все воркеры наследуют базовый класс `ManagedWorker`.
- Передача результатов из фоновых потоков в GUI выполняется **исключительно через типизированные сигналы Qt** (`Signal` / `Slot`).
- Поддерживается корректная кооперативная отмена операций (`request_stop()`) без утечек памяти и зависаний.

## 3. Картографический конвейер (MapEngine)

```
[Аэрофотоснимок JPEG / Бортовой JSON]
                 │
                 ▼
      [XMP / Metadata Parser]
  (Высота H, Roll, Pitch, Yaw, матрица)
                 │
                 ▼
        [ONNX Detector]
 (Нормализованные BBox сорняков [0..1])
                 │
                 ▼
      [Unified FramePayload]
                 │
                 ▼
       [NadirProjector]
 (Плоские координаты метрического полигона)
                 │
                 ▼
          [WeedMap Layer]
     (Точечный векторный массив)
                 │
                 ▼
       [Count / KDE Heatmap]
   (Двумерная регулярная сетка плотности)
                 │
                 ▼
        [MapExporter]
  (Экспорт в CSV, GeoJSON, PNG)
```

### Защита от потери геопривязки:
При отсутствии геопространственных тегов или при высоте $H \le 0$ движок `MapEngine` блокируется (`is_locked == True`), вызывая блокировку вкладки карты и экспорта с выводом предупреждения:
*«Геопривязка отсутствует. Доступен только просмотр исходных изображений»*.
