# RGB-детектор растений

Комплект для обнаружения растений на снимках GeosAero: модели PyTorch, ONNX и RKNN INT8, скрипты обработки изображений и расчёта метрик. Папка работает самостоятельно и может быть перенесена целиком.

Архитектура — D01 YOLOX-M с Conv stem, тремя входными RGB-каналами и одним классом `plant`. Размер входа сети — 640×640. Обработка полного кадра включает два масштаба, перекрывающиеся окна и объединение найденных рамок.

## Установка и запуск

Все команды ниже выполняются из папки `Best_model_detection_RGB`. Пути к изображениям и датасету заменяются на свои; пути с пробелами заключаются в кавычки.

### PyTorch

В Python-окружении с PyTorch:

```bash
python -m pip install -r requirements_pt.txt
python -u infer_pt.py "/path/to/image.jpg"
```

Используется `model.pt` и `settings_pt.json`. Устройство выбирается автоматически: CUDA при доступности, иначе CPU. Явный выбор и число потоков CPU:

```bash
python -u infer_pt.py "/path/to/image.jpg" --device cpu --threads 4
python -u infer_pt.py "/path/to/image.jpg" --device cuda
```

### ONNX Runtime

В Python-окружении с ONNX Runtime:

```bash
python -m pip install -r requirements_onnx.txt
python -u infer_onnx.py "/path/to/image.jpg"
```

Используется `model.onnx` и `settings_onnx.json`. По умолчанию исполнение на CPU. Для CUDA используется ONNX Runtime с CUDA Execution Provider и аргумент `--device cuda`. Число потоков CPU задаётся через `--threads`.

### RKNN на RK3588

На плате требуется `rknn-toolkit-lite2` с совместимым NPU Runtime и драйвером. В соответствующем окружении:

```bash
python -m pip install -r requirements_rknn.txt
python -u infer_rknn.py "/path/to/image.jpg" --runtime lite
```

RKNNLite загружает `model.rknn` и исполняет его на NPU. Настройки обработки находятся в `settings_rknn.json`.

### RKNN в симуляторе на компьютере

В окружении с `rknn-toolkit2` версии 2.3.0:

```bash
python -m pip install -r requirements_rknn.txt
python -u infer_rknn.py "/path/to/image.jpg" --runtime simulator
```

При каждом запуске симулятор строит INT8-граф из комплектного `model.onnx` и 200 изображений `calibration/`: целевая платформа RK3588, `optimization_level=3`, квантование `asymmetric_quantized-8`, mean=0, std=255. Построение занимает несколько минут, после чего начинается обработка кадра.

```bash
python -u infer_pt.py "/path/to/image.jpg" --output "/path/to/result.jpg"
```

Рядом сохраняется `result.json`. Поле `boxes_xyxy` содержит рамки `[x1, y1, x2, y2]` в пикселях исходного изображения, `scores` — их оценки уверенности. Начало координат — левый верхний угол. JSON также содержит размер кадра, использованный GSD, настройки и время обработки. Для отрисовки координаты округляются; в JSON сохраняются дробные значения.

## Алгоритм обработки кадра

Для всех форматов используется общий `Detector.detect(frame_bgr)`, принимающий изображение OpenCV: массив `uint8` размера H×W×3 в порядке BGR. Алгоритм определяет масштаб по ширине кадра, переводит BGR в RGB, обрабатывает окна на двух масштабах и возвращает итоговые рамки.

### Масштаб и нарезка на окна

Константы камеры GeosAero:

- ширина полного исходного снимка: `reference_width = 8192` пикселя;
- исходный GSD: `source_gsd = 0.0002736` м/пиксель, то есть 0.2736 мм/пиксель;
- политика пересчёта: `gsd_policy = "reference_width"`.

Для входного изображения шириной W:

```text
GSD = 0.0002736 × 8192 / W
```

Так учитываются уменьшенные версии полного снимка. Два прохода имеют целевые масштабы `fine_gsd = 0.0018` и `coarse_gsd = 0.0036` м/пиксель входа сети. Проход fine сохраняет больше деталей небольших растений; coarse охватывает более крупные растения и группы.

Для каждого прохода вычисляются сторона квадратного окна S и шаг:

```text
S = max(1, round(640 × target_gsd / GSD))
шаг = max(1, round(S × (1 − overlap)))
overlap = 0.25
```

По каждой оси окна начинаются с нуля и сдвигаются с этим шагом до позиции `max(0, длина_оси − S)`. Эта последняя позиция добавляется отдельно, повторы удаляются. Сочетания позиций X и Y образуют сетку окон.

Окна **перекрываются**: номинально на 25% стороны. Последнее окно прижато к границе изображения, поэтому перекрытие у края может быть больше.

Для снимка 8192×6144:

| Проход | Целевой GSD, м/пиксель | Сторона окна S | Начала по X | Начала по Y | Число окон |
|---|---:|---:|---|---|---:|
| fine | 0.0018 | 4211 | 0, 3158, 3981 | 0, 1933 | 6 |
| coarse | 0.0036 | 8421 | 0 | 0 | 1 |

В fine-проходе перекрытие соседних окон по X составляет около 25% и 80.46%, по Y — 54.10%. Coarse-окно охватывает весь снимок.

Для уменьшенного полного кадра 1280×960 GSD равен 0.00175104 м/пиксель. Fine-окно имеет сторону 658, позиции X: 0, 494, 622, Y: 0, 302; coarse-окно — 1316 с началом (0, 0). Получается также семь входов сети на кадр. На полном датасете из 103 снимков обрабатывается 721 окно.

Каждое окно вырезается из исходного изображения. Недостающая часть квадрата заполняется справа и снизу значением RGB (114, 114, 114). Затем квадрат масштабируется до 640×640 через `cv2.INTER_LINEAR`.

### Вход и выход моделей

| Формат | Подготовка входа после нарезки | Исполнение |
|---|---|---|
| PT | RGB → float32 NCHW, деление на 255 | Batch до 4 окон |
| ONNX | RGB → float32 NCHW `[1,3,640,640]`, деление на 255 | Batch=1 |
| RKNN | RGB uint8 NHWC `[1,640,640,3]`, значения 0…255 | Batch=1; нормализация mean=0/std=255 встроена в граф |

При работе с RKNN нормализация выполняется внутри графа; вход SDK передаётся в `uint8`.

Все модели выдают три сырые головы со stride 8, 16 и 32. После приведения расположения каналов их формы — `[B,6,80,80]`, `[B,6,40,40]`, `[B,6,20,20]`. Деквантованные выходы RKNN обрабатываются тем же кодом, что и выходы PT/ONNX.

Шесть каналов: `tx`, `ty`, `log_w`, `log_h`, `objectness_logit`, `class_quality_logit`. Для ячейки сетки (gx, gy):

```text
cx = (tx + gx) × stride
cy = (ty + gy) × stride
w = exp(clip(log_w, −16, 16)) × stride
h = exp(clip(log_h, −16, 16)) × stride
score = sigmoid(objectness_logit) × sigmoid(class_quality_logit)
bbox = [cx − w/2, cy − h/2, cx + w/2, cy + h/2]
```

### Возврат координат и объединение рамок

1. Отбрасываются кандидаты со score ниже 0.001. В каждом окне выполняется предварительный NMS с порогом IoU=0.95.
2. Координаты переводятся из входа 640×640 в исходный кадр: `x = x640 × S/640 + X`, `y = y640 × S/640 + Y`. Здесь X, Y — начало окна, S — его целочисленная сторона. Рамки обрезаются границами кадра.
3. Рамки всех окон одного масштаба объединяются через NMS с IoU=0.3. NMS оставляет рамку с наибольшим score и удаляет перекрывающиеся с ней рамки при IoU выше порога.
4. Применяются пороги уверенности: **0.43 для fine** и **0.5887170433998108 для coarse**.
5. Fine-рамка поглощается coarse-рамкой, если внутри coarse находится не менее 70% площади fine и площадь fine составляет не более 50% площади coarse. Доля поглощения считается относительно площади fine.
6. Оставшиеся рамки двух масштабов объединяются методом `weighted`. Coarse-рамки рассматриваются по убыванию score; каждой сопоставляется ещё не использованная fine-рамка с максимальным IoU≥0.3. Координаты пары усредняются с весами score:

   ```text
   bbox = (bbox_coarse × score_coarse + bbox_fine × score_fine)
          / (score_coarse + score_fine)
   score = max(score_coarse, score_fine)
   ```

7. Непарные рамки сохраняются. Финальный NMS с IoU=0.3 удаляет оставшиеся дубликаты.

Эта постобработка применяется ко всем трём форматам с соответствующим файлом `settings_<формат>.json`.

## Настройки

В комплекте значения настроек PT, ONNX и RKNN совпадают. Основные параметры:

| Параметр | Значение | Назначение |
|---|---:|---|
| `fine_gsd`, `coarse_gsd` | 0.0018, 0.0036 | Целевой масштаб двух проходов, м/пиксель |
| `overlap` | 0.25 | Номинальное перекрытие окон |
| `fine_confidence`, `coarse_confidence` | 0.43, 0.5887170433998108 | Пороги уверенности |
| `containment` | 0.7 | Доля площади fine внутри coarse для поглощения |
| `max_area_ratio` | 0.5 | Максимальное отношение площадей fine/coarse для поглощения |
| `box_fusion` | `weighted` | Усреднение координат сопоставленных рамок |
| `local_nms`, `global_nms` | 0.3, 0.3 | NMS внутри масштаба и после объединения |
| `inference_batch_size` | 4 | Размер пакета окон PT |

Альтернативный файл настроек передаётся через `--settings`:

```bash
python -u infer_pt.py "/path/to/image.jpg" --settings "/path/to/settings.json"
```

Аргумент `--source-gsd` задаёт фактический масштаб входного изображения в м/пиксель напрямую, переключая политику на `fixed`. Например, `--source-gsd 0.0002736`. Эти параметры доступны и в скриптах расчёта метрик. Изменение настроек влияет на итоговые рамки и показатели точности.

## Расчёт метрик

Ожидаемая структура датасета:

```text
GeosAero_hitech_dataset/
├── GAS_202608281553_032_web/
│   └── изображения
└── GAS_202608281553_032_mark_web/
    └── annotations_coco.json
```

Запуск в окружении соответствующего формата:

```bash
python -u evaluate_pt.py --dataset "/path/to/GeosAero_hitech_dataset"
python -u evaluate_onnx.py --dataset "/path/to/GeosAero_hitech_dataset"
python -u evaluate_rknn.py --runtime simulator --dataset "/path/to/GeosAero_hitech_dataset"
python -u evaluate_rknn.py --runtime lite --dataset "/path/to/GeosAero_hitech_dataset"
```

Каждый кадр обрабатывается тем же вызовом `Detector.detect(frame_bgr)`, что и при обычном инференсе. После получения предсказаний аннотации используются для расчёта метрик. Все категории разметки оцениваются как класс `plant`. Координаты аннотаций приводятся к фактическому размеру изображения: для кадра 0076 с фактическим размером 1280×960 вместо объявленного 8192×6144 применяется коэффициент 0.15625.

В консоль выводятся F1, Precision, Recall, TP, FP и FN. В `results/metrics_pt/`, `results/metrics_onnx/` или `results/metrics_rknn/` сохраняются:

- `metrics.json` — общие метрики, настройки и время выполнения;
- `per_image.json` — TP, FP и FN каждого изображения;
- `predictions.jsonl` — итоговые рамки и score каждого изображения.

Повторный запуск перезаписывает результаты. Другая папка задаётся через `--output "/path/to/metrics"`. Для быстрой проверки на первых N изображениях используется `--limit N`; для полного расчёта этот аргумент опускается.

| Формат / исполнение | AP50 | mAP50:95 |
|---|---:|---:|
| PT, CPU FP32 | 79.85% | 57.25% |
| ONNX Runtime, CPU FP32 | 79.85% | 57.26% |
| RKNN INT8, симулятор Toolkit2 | 80.82% | 49.11% |

Правила расчёта:

- TP засчитывается при IoU≥0.5. Предсказания сопоставляются с разметкой по убыванию score; каждой размеченной рамке соответствует максимум одно предсказание.
- Счётчики TP, FP и FN суммируются по всем изображениям, включая пустые кадры.
- `Precision = TP/(TP+FP)`, `Recall = TP/(TP+FN)`, `F1 = 2TP/(2TP+FP+FN)`.
- AP рассчитывается по непрерывной огибающей Precision–Recall для итоговых детекций после фиксированных порогов уверенности. mAP50:95 — среднее AP при IoU от 0.50 до 0.95 с шагом 0.05.

Исходные отчёты измерений: `benchmarks/pt_cpu.json`, `benchmarks/onnx_cpu.json`, `benchmarks/rknn_simulator.json`.
